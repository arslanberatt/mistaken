## Architecture Decisions

- **Tauri 2 + React + TypeScript**: provides a cross-platform desktop shell while allowing native Rust integration for local audio and ASR.
- **Rust native core**: audio capture and local inference need predictable native resource control and should not run in the webview.
- **No paid/cloud ASR**: core transcription must have zero per-minute transcription cost and no API-key dependency.
- **Local ASR abstraction**: prevents the whole app from becoming coupled to one model/runtime and allows accuracy benchmarking.
- **sherpa-onnx first evaluation target**: supports native offline speech-recognition workflows and related local speech tooling.
- **whisper.cpp as benchmark/fallback candidate**: useful local comparison path, but not automatically selected as the primary recognizer.
- **Model selection by benchmark, not assumption**: Mistaken requires preservation of incorrect English, so generic ASR reputation alone is insufficient.
- **ASR maturity split:** `DevelopmentOnly` permits Specs 06/09–11 architecture work with explicit non-release labeling; `ProductionApproved` requires a later Spec 05 gate pass and is mandatory for Spec 12 `PASS`, packaging, and Spec 15 `RELEASE-READY`.
- **Separate model-license review**: an open-source runtime does not automatically imply every model weight can be redistributed under the same terms.
- **WASAPI Loopback on Windows**: native Windows path for system-output capture without requiring a paid service or virtual cable as a core dependency.
- **ScreenCaptureKit on macOS**: native Apple path for system-audio capture.
- **Source-based speaker separation**: microphone/system source metadata is more reliable than diarization for the normal two-person workflow.
- **Two independent ASR sessions**: microphone and system audio are never mixed before transcription.
- **In-memory transcript only**: avoids building a persistence system that is unnecessary for the user's workflow.
- **No grammar correction in app**: the transcript is evidence of the user's spoken English and must not be intentionally cleaned before Obsidian analysis.
- **Obsidian is external**: Mistaken outputs copyable plain text and does not need vault access.
- **Read/copy-only V1 transcript**: users may select and copy transcript text, but manual editing is out of scope.
- **Clear confirmation boundary**: `Clear` requires confirmation whenever finalized transcript content exists; interim-only content may be cleared directly.
- **Final-only Copy All**: clipboard serialization excludes unstable interim segments, preserves first-seen final order, adds `- ` only from structural system-source metadata, and performs no text normalization or correction.
- **Parallel delivery by dependency and path ownership**: 15 specs run in separate Git worktrees only when their predecessors are merged and their exact owned paths do not overlap; one integration owner controls shared files and context updates.
- **High-author, tiered implementation**: high-reasoning models author/finalize every spec; medium models may implement deterministic bounded units, while native audio, ASR, licensing, real-time lifecycle, acceptance, and final integration stay high-model work by default.
- **Typed runtime boundary:** Four application commands (`get_runtime_snapshot`, `list_microphones`, `start_capture`, `stop_capture`) and six main-webview native events form the reviewed shared spine; values are runtime-validated, status ordering uses monotonic revisions, and structured error codes—not message text—drive behavior.
- **Truthful pre-backend behavior:** Before audio/model specs land, snapshot reports unavailable resources and operational commands reject predictably without fake devices, fake success, or native resource allocation.
- **Listener and permission containment:** Frontend listeners register before snapshot, clean up asynchronous/partial registration safely, and receive small JSON events only; the `main` capability grants exact application commands and listen permission but no frontend emit or wildcard access.
- **Cross-platform microphone adapter:** CPAL `0.18.2` with stable device IDs is the reviewed V1 microphone I/O boundary; ASIO, JACK, browser media, virtual drivers, and cloud capture are excluded.
- **Bounded PCM handoff:** Microphone capture downmixes to native-rate mono `f32` in preallocated 20 ms blocks; exactly 100 reusable blocks bound queued PCM to two seconds, and callback overflow drops newest frames without blocking or allocation.
- **Honest pre-ASR test:** Spec 04 exposes a separate local `Test microphone` flow and keeps production `Start Listening` disabled until Spec 06 provides approved ASR; no PCM or continuous level crosses IPC.
- **Microphone permission timing:** macOS authorization is checked/requested only from explicit Test using the bundled usage description; Windows desktop privacy denial is reported from observable native behavior and never inferred from silence.
- **Wave 3 shared ownership:** Spec 04 is the sole Wave 3 writer for root Cargo/runtime/UI microphone integration; Specs 07–08 keep platform system-audio implementations and manifests isolated until Spec 09 performs shared wiring.
- **Fidelity outranks WER:** Model approval is driven first by mistake-preservation rate over annotated error spans (≥ 0.90, with ≤ 0.05 false-correction rate) and only then by word error rate (≤ 0.25 corpus, ≤ 0.12 fluent control); a lower-WER model that silently fixes grammar loses to a higher-WER model that preserves it.
- **Frozen Spec 05 gates:** Latency ≤ 900 ms median first partial and ≤ 1500 ms p95 final-after-endpoint; RTF ≤ 0.6 single-stream and ≤ 0.9 dual-stream; peak RSS ≤ 700 MB per stream and ≤ 1.4 GB for two; zero non-empty output on physical-silence clips; model payload ≤ 120 MB uncompressed for bundling. Lowering a gate requires a recorded product decision, not a spec edit.
- **Reference benchmark hosts:** `mac-arm64` (Apple Silicon, ≥ 8 cores, ≥ 16 GB, AC power; the M4 development host qualifies) and `win-x64` (≥ 8 cores, ≥ 16 GB, AC power). Both must pass every gate; one host's result never substitutes for the other's.
- **Pinned candidate set:** sherpa-onnx streaming Zipformer `en-2023-06-26` int8/fp32 (left-64) and `en-20M-2023-02-17` int8, plus whisper.cpp `base.en`/`small.en` ggml as non-streaming comparisons; runtimes are built from exact release tags and every model file is pinned by byte size and SHA-256. The `en-2023-06-21` variant is excluded because its GigaSpeech training terms are unresolved.
- **Separate license and provenance verification:** sherpa-onnx is Apache-2.0, ONNX Runtime and whisper.cpp are MIT, and the candidate model cards declare Apache-2.0/MIT, but the `2023-06-26` upstream TorchScript repository declares no license and LibriSpeech is CC BY 4.0 with an attribution duty; an unresolved provenance chain blocks approval regardless of accuracy.
- **No audio or weights in Git:** The benchmark corpus commits prompts, protocol, verbatim references, error-span annotations, and per-clip checksums, while recordings, model files, vendored runtime sources, and run hypotheses stay local and ignored; speakers are opaque profile ids with a consent flag and no demographic data.
- **Honest streaming comparison:** whisper.cpp has no native streaming recognizer, so its adapter reports `simulated-rolling-window` and its latency numbers are never presented as streaming latency.
- **Official version-matched recognizer binding:** The shipped ASR boundary is the `sherpa-onnx` Rust crate published in lockstep with the C++ project (`sherpa-onnx = "1.13.8"` upstream), linked statically behind an internal `StreamingRecognizer` trait. The third-party `sherpa-rs` crate is rejected because its repository is archived.
- **Verified offline linking:** The crate's build script downloads a prebuilt inference archive when no override is set, so Mistaken builds must set `SHERPA_ONNX_ARCHIVE_DIR`/`SHERPA_ONNX_LIB_DIR` to a locally staged archive verified by size and SHA-256 (`osx-arm64-static-lib` 20,965,936 B / `9091bf16…`; `win-x64-static-MT-Release-lib` 123,206,268 B / `56ffcf3c…`). An unverified build-time binary download is a supply-chain defect.
- **No resampling crate, one rate per stream:** `sherpa-onnx/csrc/features.cc` creates a `LinearResample` internally when the fed rate differs from 16 kHz, so the microphone path needs no resampler; the same code calls `SHERPA_ONNX_EXIT(-1)` if a stream later sees a different rate, so each recognizer stream is fixed to one sample rate for its life and a format change forces a new stream.
- **Model lifecycle:** Launch checks presence by metadata only; the approved model loads lazily on first Start after every file's size and SHA-256 is verified against a compiled-in manifest copied from Spec 05's approval, then stays cached for the process lifetime. Mismatch is `model_unsupported`, absence is `model_missing`, and there is no download, no second location, and no alternate-model fallback.
- **Two bounded audio stages:** Spec 04's 100 × 20 ms capture pool (2 s) stays, and Spec 06 adds a 30 × 100 ms inference pool (3 s) fed by copying out of the capture block and recycling it immediately, so decoding can never stall capture; saturation drops newest samples and emits at most one `inference_lagging` per second while capture continues.
- **Transcript emission contract:** Segment id `mic-<sessionId>-<segmentIndex>` carries every partial and its final; partials are throttled to one per 150 ms and never empty; endpoint produces exactly one immutable final; times are audio time from fed-sample counts, not wall clock; text is emitted verbatim apart from whitespace trimming/collapsing.
- **All rewriting features off by construction:** hotwords, homophone replacement, `rule_fsts`/`rule_fars`, CTC FST decoding, punctuation/ITN models, and any word-substitution table are absent or explicitly disabled; endpoint rules are frozen at 2.4 s / 1.0 s / 15 s and verified against Spec 05's latency gates.
- **Clean cutover at Spec 06:** Production Start Listening/Stop becomes the single microphone capture action and Spec 04's temporary `Test microphone` diagnostic is removed, so no duplicate capture path or stale "transcription unavailable" copy survives.
- **macOS system-audio minimum is 13.0:** ScreenCaptureKit's `SCStream` exists from 12.3, but every audio property (`capturesAudio`, `sampleRate`, `channelCount`, `excludesCurrentProcessAudio`) is macOS 13.0+, so 12.3 would ship a build whose system-audio half cannot work. The adapter also checks the running version at start and returns an explicit unsupported error; CoreAudio process taps (14.2+) are rejected to avoid a second permission model.
- **Audio-only ScreenCaptureKit, no pixels:** `SCStream` requires a content filter, so Mistaken must request the Screen Recording permission for audio-only capture and says so plainly. Exactly one audio stream output is registered, non-audio deliveries are counted and ignored, the nominal 2×2/1 fps configuration is documented as never consumed, and no image, frame, or file is ever read or written.
- **Honest screen-recording permission:** availability is decided by the TCC-gated `getShareableContentWithCompletionHandler` result; the redacted `getCurrentProcessShareableContent…` API is banned because it returns content without user consent and would fabricate availability. A distinct restart-required state exists instead of a generic failure, and nothing prompts outside an explicit start.
- **macOS capture format:** stereo 48 kHz is requested (framework default, avoids relying on ScreenCaptureKit's undocumented resampler), the delivered format description is validated every time instead of assumed, a mid-session rate change is rejected before it can reach the recognizer, and one downmix stage produces exact 20 ms mono blocks symmetric with the microphone path.
- **Platform adapters are standalone crates:** Specs 07 and 08 ship `crates/<platform>-system-audio/` with their own manifests/lockfiles, no dependency on the app crate, Tauri, serde, or ASR, and an explicit mapping table onto Spec 03's `AudioError`/`RuntimeError` that Spec 09 implements. Required shared-file changes (for example `minimumSystemVersion: "13.0"`) are recorded and yielded to the integration owner, never edited from a platform worktree.
- **Windows minimums, two numbers:** API floor is Windows 10 1703 (build 15063), because event-driven loopback receives no events below it and Microsoft's documented workaround needs a second render stream purely for pacing — refused. Supported and tested floor is Windows 10 22H2 (build 19045) / Windows 11; builds in between run the same code and are recorded as untested. Per-process loopback is excluded with per-application capture.
- **Windows loopback has no permission gate:** render-endpoint loopback needs no prompt, no elevation, no driver, no virtual cable, and no "Stereo Mix" device, so the Windows adapter exposes no permission API and no error kind maps to `system_audio_permission_denied`. Copying the macOS permission wording to Windows is prohibited; the real effect of the desktop microphone privacy toggle is measured and recorded.
- **Honest continuous timeline on Windows:** WASAPI loopback delivers no packets while the endpoint is idle, so the adapter reconstructs time from device position, fills the measured gap with zero frames capped at 10 s, resynchronizes on cap or discontinuity, treats `AUDCLNT_BUFFERFLAGS_SILENT` as zeros without reading the buffer, and keeps `captured_frames`, `silent_flag_frames`, and `synthesized_frames` as separate counters. No report may present synthesized silence as captured audio, and synthesized silence never satisfies a "receiving" activity condition.
- **Default-endpoint change must be detected:** switching the default output while the old device still exists does not invalidate the audio client, so capture would continue on a device nobody hears. The adapter compares the default render endpoint id at most once per second and ends the session with a distinct `EndpointChanged` kind; `IMMNotificationClient` is the recorded alternative, rejected to avoid implementing a COM callback interface for one boolean.
- **Windows capture format and COM hygiene:** the endpoint mix format is requested as-is (no `AUTOCONVERTPCM`, no driver-side converter) and converted in one tested stage covering 32-bit float and 16/24/32-bit integer PCM with `WAVEFORMATEXTENSIBLE` subformat discrimination; the session rate is fixed at `Initialize`; COM is initialized MTA on the adapter's own capture thread and uninitialized there after every interface is released, never on a Tauri-owned thread.
- **Documented Windows capture limits:** DRM-protected content is not captured by a trusted driver and is indistinguishable from genuine silence, loopback carries the whole session mix rather than one application, and Remote Desktop redirects audio to session-specific devices. These are stated to users rather than treated as defects, and WASAPI offers no per-process exclusion, so any future Mistaken audio output becomes a feedback constraint for Specs 09–10.
- **Atomic dual-source start:** `startCapture` accepts microphone-only, system-only, or both, and rejects the no-source request as `invalid_request`. Every requested source must reach a playing stream with a live recognizer stream or the whole start fails and rolls back both sources, because silently transcribing one side of a conversation the user asked to capture in full produces a trustworthy-looking but incomplete transcript. Opting out is an explicit user action.
- **Total source isolation, one shared recognizer:** each source owns its platform capture, 100 × 20 ms pool, 30 × 100 ms inference stage, `OnlineStream`, worker thread, segment index, status, and counters; only the loaded recognizer is shared as `Arc` (the crate documents `Send + Sync`), so model memory is paid once and in-memory audio stays bounded at 10 s total. `decode_multiple_streams` stays unused in V1 to avoid head-of-line blocking between sources; it is a recorded Spec 12 CPU candidate.
- **Structural attribution only:** `AudioSource` travels from the platform backend through pool, stage, and worker into `TranscriptSegment.source`; nothing infers source from text, energy, timing, order, or a default, a source-mismatched block is a fatal `internal` error rather than a correction, and zero cross-attribution across scored utterances including deliberate overlaps is a blocking criterion.
- **Cross-source order is emission order:** within a source finals are non-decreasing in `endedAtMs`; across sources visible order equals finalization order through Spec 02's first-seen ordering. A 1–2 s reorder window keyed on `startedAtMs` was rejected: it delays every final, contradicts the frozen reducer contract, and cannot make genuine cross-talk linear. Timestamps come from one session clock origin plus per-source fed-frame counts so the two sources remain comparable without timestamp sorting anywhere.
- **No `- ` in native code:** the system prefix exists only in Spec 02's formatter output from `source === "system"`; a `- ` in any native transcript payload is a defect with its own acceptance criterion.
- **Honest partial degradation after start:** a source dying mid-session marks only that source as failed with its exact code and `source`, tears down only its resources, leaves the survivor transcribing, and never deletes, rewrites, or reorders finalized transcript content; `captureStatus` stays `listening` while any requested source captures and becomes `error` only when all have failed. Automatic retry and reconnect belong to Spec 10.
- **System audio is opt-in and volatile:** the toggle defaults to off and is never persisted, so no macOS screen-recording prompt is reachable without an explicit user action, and per-source error copy is keyed off codes per platform — macOS Screen Recording guidance never appears on Windows and Windows failures never borrow permission wording.
- **Bounded, visible recovery only:** transient source-local failures (Windows `EndpointChanged`/`DeviceInvalidated`/`AudioServiceDown`, macOS `StreamStopped`, microphone disconnect) retry at most 3 times per source per session with 500 ms/2 s/5 s backoff, show `Reconnecting … attempt N of 3`, and reset the budget after 60 s of healthy capture with real signal. Permission, platform-version, model, format, and `internal` failures never retry, because they are user-owned or permanent; exhaustion is terminal with the underlying reason preserved.
- **Recovery must satisfy the frozen reducer:** a recovery keeps the session id and id format, continues the per-source segment index (only a new session resets it), abandons the failing source's in-flight interim without a final, creates a fresh recognizer stream per attempt (the device rate may have changed, and reusing a stream would trip the fatal `SHERPA_ONNX_EXIT` path), and clamps the restarted offset to ≥ that source's last emitted `endedAtMs` so timestamps stay monotonic. The lost audio is simply absent — no synthesized gap, no transcript annotation.
- **Degradation is visible, never automatic:** sustained lag (>20 % dropped inference blocks in a 10 s window) enters a distinct degraded state per source and leaves it after a clean window, while `inference_lagging` stays ≤1/s per source. The app never changes thread counts, model configuration, sample rates, endpoint rules, or source enablement in response to load, so runtime behavior stays identical to what Spec 05 benchmarked and Spec 12 accepts.
- **Failures are contained, transitions are bounded:** every native worker body catches panics and converts them to a source-terminal `internal` error with full release and sanitized detail; a poisoned lock ends the session rather than reusing untrusted state; no lock is held across capture, permission, stream, join, backoff, recognizer, or emission work; `starting` is watchdog-bounded at 10 s (excluding the user-driven macOS prompt) and `stopping` at 3 s, so the UI can never sit in a transitional state.
- **One shutdown path, honestly scoped:** a single idempotent native `shutdown()` releases both sources and is invoked from the window close event, Tauri's `ExitRequested`/`Exit` handling, and `SIGINT`/`SIGTERM`/console-close, never depending on React cleanup. `SIGKILL` and power loss are stated as unhandleable rather than claimed graceful, and nothing about a failure, retry count, or device is persisted across launches.
- **Long-run trust is measured:** a 60-minute continuous dual-source soak on each reference host samples RSS, thread and handle counts, per-source counters, and audio-time drift at least every 5 minutes; RSS growth after minute 5 must stay within 5 %, thread and handle counts must be flat, and repeated recoveries must leave no allocation ratchet. The transcript is the only permitted monotonic growth.
- **Release panic strategy is `unwind`, not `abort`:** Spec 10's panic-containment invariant depends on `std::panic::catch_unwind` at four native worker sites (`asr::worker`, `audio::microphone::session`, `audio::system::session`, `state::manager::schedule_recovery`), which is a no-op under `panic = "abort"`. `src-tauri/Cargo.toml`'s `[profile.release]` therefore keeps `panic = "unwind"` (diverging from Tauri's stock size-optimization guideline) while keeping `codegen-units = 1`, `lto = true`, `opt-level = 3`, and `strip = true` for size; `src-tauri/src/lib.rs` fails the build at compile time if `panic = "abort"` is ever reintroduced.
- **Waves 6 parallel split is exact:** Spec 10 owns native lifecycle plus `src/features/audio/**`; Spec 11 owns `src/App.tsx` and `src/features/transcript/**`. Needs crossing that line are recorded and yielded to the integration owner, and neither spec may widen Spec 09's frozen event union.
- **Platform-correct, non-hijacking shortcuts:** one cleaned-up window listener handles only `Cmd/Ctrl + Enter` for Start/Stop and `Cmd/Ctrl + Shift + C` for Copy All, rejects repeat/composition/disabled cases, and calls `preventDefault()` only after handling; `Space`, native selection, platform copy/select-all, and text navigation remain untouched.
- **Follow only with user consent:** transcript auto-follow is active only within 64 px of the bottom; every user scroll beyond that threshold detaches it, and new finals, interim growth, status changes, or recovery events must leave detached `scrollTop` unchanged. Scrolling back or activating the accessible `Jump to latest` button restores following.
- **Interims stay readable but silent:** the named transcript `role="log"` keeps its implicit polite behavior for finalized rows, while each interim subtree overrides it with `aria-live="off"` so up to roughly 13 dual-source interim mutations per second cannot flood VoiceOver or Narrator. Finals are announced once without a mirrored live region; real assistive-technology evidence remains mandatory.
- **Bounded frontend lifecycle:** owned UI code may create exactly one keydown listener, one scroll listener with at most one outstanding animation frame, one reduced-motion listener, one elapsed interval while listening, and one copy-feedback timeout. Every resource has an explicit unmount/state-transition cleanup path, elapsed time is recomputed from its start instant rather than tick-counted, and reduced-motion falls back to instant scrolling.
- **Long transcripts are measured before abstracted:** with roughly 1,000 finalized segments, one interim update must rerender only its row plus the container. Virtualization, truncation, or a second transcript store is prohibited unless measured failure is recorded as a later integration-owner decision.
- **Acceptance is a serialized whole-app gate:** Spec 12 begins only after Specs 10 and 11 merge, uses one writer because measured defects may require root-cause fixes anywhere, and authorizes Specs 13/14 only from one reviewed post-acceptance SHA.
- **Offline proof requires prevention and observation:** every measured build/run has no non-loopback route, while per-process permitted and blocked attempts are traced; an attempted DNS/socket/HTTP connection fails even when offline networking prevents success.
- **Privacy is content-aware and boundary-honest:** transcript sentinel scans, browser-storage inspection, file-write traces, PCM flow review, and log scans prove no user-content persistence; unavoidable OS/WebView metadata is classified rather than denied, and explicit final-only Copy All remains the sole user-owned clipboard boundary.
- **Integrated performance uses exact gates:** real-app visible latency keeps Spec 05’s ≤900 ms median partial and ≤1500 ms p95 final thresholds; process-tree CPU/RSS use one-second samples, normal flow requires zero drops, overload must remain fixed-capacity and visible, and each host repeats a final-binary 60-minute dual soak.
- **Packaging inputs freeze at Spec 12:** version is `0.1.0`; the approved ≤120 MB model is bundled under the one `$RESOURCE/resources/models/<model_id>/` layout with shared third-party notices; model/runtime/config identities and every committed lockfile are frozen before Specs 13 and 14 branch.
- **Acceptance verdicts fail closed:** a host is `PASS` only with every applicable real-host criterion and no High/Medium finding; runnable defects are `FAIL`, external missing prerequisites are explicit `BLOCKED`, and the cross-host result passes only when both hosts pass.
- **macOS V1 distribution is Apple Silicon only:** Spec 13 emits `aarch64-apple-darwin` artifacts and requires real macOS 13.x Apple Silicon floor evidence. Intel/universal support is excluded until its runtime archive, model, size, and real-host behavior pass the same gates.
- **macOS ships as `.app` plus standard DMG:** Direct distribution outside the Mac App Store uses Tauri’s drag-to-Applications DMG. `.pkg`, App Store/TestFlight, Homebrew, custom DMG marketing art, privileged helpers, launch agents, and public upload are excluded.
- **No macOS updater path:** Tauri Updater, Sparkle, update endpoints/keys/artifacts, background checks, and differential updates remain absent; a future version is a new manually installed artifact unless a later product decision creates a separate spec.
- **Developer ID trust is explicit:** A macOS `PASS` artifact requires `Developer ID Application` signing, hardened runtime, secure timestamp, accepted `notarytool` result with inspected log, a stapled ticket, Gatekeeper assessment, and a quarantined Finder install that launches offline without bypass.
- **macOS stays non-sandboxed with an empty entitlement baseline:** Direct Developer ID V1 does not enable App Sandbox. Hardened-runtime exceptions, sandbox audio-input access, `get-task-allow`, JIT/unsigned-memory, dyld, debugger, and library-validation exceptions are absent unless a real signed-build failure proves one exact Apple-documented requirement and full review/rerun approves it.
- **macOS permission manifest is minimal:** `NSMicrophoneUsageDescription` is exactly `Mistaken uses your microphone to transcribe your speech locally on this Mac.` Apple publishes no Screen Recording purpose key, so none is guessed; ScreenCaptureKit permission truth comes from the real built flow.
- **Packaging reproducibility is semantic, not falsely byte-identical:** Two clean ad-hoc builds from one SHA must have identical normalized payload manifests; timestamped signatures, notary tickets, and DMG container metadata are closed documented exclusions. The final stapled DMG receives one immutable SHA-256 after its last mutation.
- **Packaging blockers stay narrow:** Missing Developer ID/notary credentials, Apple notary service availability, or a qualifying macOS 13.x Apple Silicon floor host may produce explicit `BLOCKED` fields only after every reachable criterion passes. Ad-hoc output is local evidence and is never distributable or a `PASS`.
- **Windows V1 distribution is x64 only:** Spec 14 emits `x86_64-pc-windows-msvc` artifacts; ARM64 and 32-bit are excluded until a benchmark, runtime archive, and real-host evidence exist for them. The declared floor stays Windows 10 22H2 build 19045 / Windows 11, with the 15063–19044 API-floor range explicitly untested.
- **Windows ships one per-user NSIS setup executable:** `Mistaken_0.1.0_x64-setup.exe` installs under `%LOCALAPPDATA%` with `installMode: currentUser`, no UAC prompt, no elevation manifest, no service, no scheduled task, no `Run`/startup key, and no driver. MSI/WiX, MSIX, Microsoft Store, winget/Chocolatey, portable ZIP, and a second installer artifact are excluded.
- **WebView2 is embedded as the Evergreen offline installer:** `webviewInstallMode: offlineInstaller` (~127 MB) is frozen so installation works with networking disconnected. `downloadBootstrapper`/`embedBootstrapper` are rejected for requiring internet at install time, `skip` for silently breaking launch, and `fixedVersion` for shipping an unpatched engine over 250 MB with UNC and Windows 10 `icacls` constraints.
- **No Windows system dependency:** `build > windows > staticVCRuntime` stays `true` and `bundleVCRuntime` stays `false`; with Spec 06's static `win-x64-static-MT-Release-lib` archive and Spec 08's no-redistributable finding, the installer adds no Visual C++ Redistributable, .NET, driver, or virtual audio device.
- **Windows packaging needs one pinned online staging phase:** the Tauri bundler fetches NSIS tooling and the WebView2 offline installer on a cold cache, so Spec 14 separates a traced, digest-pinned staging step restricted to documented Tauri/Microsoft hosts from the measured offline build instead of claiming a fully offline cold build.
- **Authenticode trust is explicit and honest:** a Windows `PASS` artifact requires SHA-256 signatures with an RFC 3161 timestamp on both the setup and application executables, a passing `signtool verify /pa /all`, and a real download-path install as a standard user. Observed SmartScreen/Defender behavior is recorded as evidence; disabling or bypassing a Windows security control, or promising a prompt-free first run, is prohibited.
- **Windows uninstall honesty:** uninstall must remove the application directory, embedded model, notices, shortcuts, and the `HKCU` uninstall entry, while the Microsoft-owned WebView2 runtime and its user-data folder are classified as retained OS state rather than falsely claimed removed.
- **Wave 8 ownership is isolated per platform:** Spec 13 owns only `src-tauri/tauri.macos.conf.json`, macOS `Info.plist`/evidenced entitlement file, `icon.icns`, and `distribution/macos/**`; Spec 14 owns only `src-tauri/tauri.windows.conf.json`, `icon.ico`, an evidenced NSIS hook file, and `distribution/windows/**`. Any frozen shared-input correction returns to the integration owner and restarts both branches from one reviewed SHA.
- **Release is one candidate, not two platform successes:** Spec 15 accepts only two artifacts provably built from one release SHA at version `0.1.0` with identical frozen inputs; differing packaging base SHAs, a stale artifact, or a payload difference outside the documented platform set is a release-blocking defect, and any fix rebuilds both artifacts and reruns every invalidated criterion on both platforms.
- **Release acceptance is serialized:** Spec 15 has one writer and no parallel peer, because it may fix defects anywhere; a concurrent change landing during the run invalidates every artifact-dependent measurement.
- **Release evidence measures the installed artifact:** every runtime criterion runs against the signed, downloaded, clean-account installation on four hosts (macOS primary and 13.x floor, Windows 11 and 10 22H2 floor) with networking disabled, including the Spec 12 corpus protocol, Spec 05 gates unchanged, and one 60-minute installed dual soak per platform. Development-build or single-platform evidence is never accepted.
- **Parity is structural, not textual:** one identical scripted conversation must yield structurally identical `Copy All` output, states, control enablement, and accessibility semantics on both platforms; recognition text may differ, structure may not, and the only allowed differences are the documented platform permission guidance and native affordances.
- **Release evidence has its own closed schema:** Spec 12's schema and scenario thresholds stay frozen and read-only, so Spec 15 adds `release/schema.json` plus `manifest.json`, `CHECKSUMS.txt`, `RELEASE_NOTES.md`, `ROLLBACK.md`, `PUBLICATION.md`, and `release/evidence/**`, with tests rejecting contradictions such as `RELEASE-READY` alongside any `FAIL`/`BLOCKED` gate, an unsigned artifact, or an open High/Medium finding.
- **Publication is gated on an explicit destination:** no distribution host, domain, or account is chosen by the project. Artifacts, checksums, notes, rollback checklist, and a local annotated `v0.1.0` tag are produced unconditionally; actual upload happens only with a user-supplied destination and credentials, otherwise publication is exactly `BLOCKED` and nothing is uploaded or pushed.
- **Rollback assumes no updater:** since neither platform ships an update mechanism, release response is withdrawal plus a replacement statement, checksum invalidation, recorded revert order, and - on identity compromise - hash/submission-id preservation, issuer revocation, and rebuilding under a new identity, with users told to remove and reinstall manually.
- **Documentation reconciliation is a release criterion:** every spec's evidence record must be filled from real runs with no `Pending` field left, every context statement must match shipped reality with each correction and reason recorded, and canonical documentation must live in the repository rather than the synced staging bundle.
